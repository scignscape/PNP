{\LARGE \fontfamily{bch}\fontseries{eb}\selectfont \setlength{\leftmargini}{3pt}\begin{description}
\item[Support both query and scripting languages] {\labelsp} There are use cases for both 
forms of computer language in Research Object contexts     
\vspace{8pt}
\item[Minimize External Dependencies] {\labelsp}  As much as possible, langauge 
compilers and runtimes should be built directly from source files internal to data sets  
\vspace{8pt}
\item[Customizable] {\labelsp} It should not take extensive extra coding to 
add syntactic and runtime features designed specifically for individual data sets  
\vspace{8pt}
\item[Focus Language Design around Research and FAIR Sharing] {\labelsp}  Special 
languages inside data sets are not intended to be general-purpose scripting 
languages.  Instead, their syntax and semantics should be focused 
on the goal of documenting research methods, theories, and data models
\vspace{8pt}
\item[Provide Compiler and VM Support for Desired Language Features] {\labelsp}  Design 
by Contract, unit-decorated types, coordinate-system-specific types, 
multiple-dispatch, MVC architecture, and other patterns for semantically 
detailed languages require bottom-up support vis-\`a-vis instruction sets and runtime state
   
\end{description}}\end{minipage}
